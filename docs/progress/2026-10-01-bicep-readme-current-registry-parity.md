**Status**: blocked

**Updated**: 2026-10-01
**Branch**: `jaredfholgate-bicep-static-check-parity`

## Outcome

Make Bicep build, lint, validation, and README rendering non-restoring under
`AVM_OFFLINE=1`, and report source-less READMEs explicitly without blocking
source-backed rendering. Audit registry input before crediting pinned
assertion M:651. The historical pinned checkout had a Vault comment
difference and an HCI source/README version difference. Registry main has
since corrected HCI, but its published dependency has not been qualified
for an unmodified offline render.
`avm.bicep.convention-incomplete` stays in place. Do not switch registry CI.

source-backed READMEs, rendered 574, and matched 573 exactly. It reported
three source-less READMEs as `NotRendered` warnings, never as generated
matches. The Vault root is the one rendered mismatch: its generated output
adds exactly eight JSON example comment lines (four `Required parameters`
and four `Non-required parameters`) and no other differences. The tracked
SHA-256 is `72BEFB145543D707BA849143ECCB8D4B17EFE2B09385156E6A5CC1B7060D8E01`;
the generated SHA-256 is
`DE837FEEE2890A3BAB192282FB19F5D8FB80A8D7D2315BBF85BF425220890066`.
This is the same *kind* of difference as the frozen comparison, but is
still a real current-head `avm.bicep.docs-stale` result.

The unrendered source-backed path is
`avm/res/azure-stack-hci/virtual-machine-instance/README.md`: its source
references `br/public:avm/res/hybrid-compute/machine:0.6.0`, unavailable
in the local Bicep cache. `docs generate --no-restore` returned BCP190,
which `avm docs` reported as `avm.bicep.docs-render-failed`, not a pass.
The immutable registry release tag for that dependency points to
`5c7c9f9b53c787e5cc1116a713b9981a4f7acdbc`; its `main.bicep`,

does **not** verify the live OCI artifact or replace an unmodified,

## Registry main correction after the audit

Registry main at `dd8842c373ca793bac99037a19f0d68023e9b63d`
already contains the one-line HCI README correction, merged via
[Azure/bicep-registry-modules#7430](https://github.com/Azure/bicep-registry-modules/pull/7430).
README line 595 now references `machine:0.6.0`, matching the unchanged
`main.bicep` line 105. Read-only pinned GitHub verification found the
README blob `b7b23761e0708dc48858263ce7aa6d57f75fb632`
(SHA-256 `390B2DD76984C9787BAB0FF1670D86EC080731B387908F16698EFB7FA0749A24`)
and source blob `d5f00262b862cac01270017bdb519fc75e3bf8fc`
(SHA-256 `405DBDD1A53BEE7FCDDA89C0AA7510ED2B184D9652D941821EB80D879D377FAB`).
The old README version mismatch is historical; no duplicate upstream patch
is needed.

The Vault README at this newer commit retains the historical blob
`427057a4dc54ea16daa70e3f05d5a379b7b43319` and its five JSON
examples (first comment pair present, four absent). Its tracked bytes
have not changed; this does not establish newly generated bytes or
qualify a full current-head comparison.

The earlier cache recheck used a nested repository path rather than Bicep's
canonical `$`-encoded cache path, so it did not establish whether the exact
`machine:0.6.0` artifact was present. The historical `--no-restore` build
did fail with BCP190. No MCR request, restore, or current-head README render
was performed. Pinned HCI `main.bicep` also directly imports
`br/public:avm/utl/types/avm-common-types:0.5.1` at line 37; the canonical
cache directories for these dependencies were not inspected. The historical 574/575
render count cannot be promoted to an independently qualified result for
this newer commit.
